Полнофункциональный, полностью автоматизированный и идемпотентный скрипт установки связки **SelfSteal** (Nginx маскировка Reality) и **RemnaNode** (узел RemnaWave) для чистого сервера **Ubuntu**.

Скрипт превращает сложный ручной процесс настройки сертификатов Let's Encrypt, Unix-сокетов, обхода зависаний `needrestart` и конфигурирования Docker Compose в **запуск одной команды**.

---

## ⚡ Быстрый старт (One-Liner)

Выполните команду на сервере с правами `root`:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Dopeobg/remnanode-selfsteal-installer/main/install.sh)
```

> **Совет:** Скрипт корректно работает даже при передаче через пайп (`curl ... | bash`), автоматически определяя интерактивный TTY для ввода данных.

## 📋 Системные требования

- **ОС:** Ubuntu 20.04 LTS, 22.04 LTS, 24.04 LTS (или Debian 11/12).
- **Права:** `root` (UID 0).
- **Свободные порты:** 80 (HTTP для Let's Encrypt), 2222 (RemnaNode communication).
- **Домен (FQDN):** Зарегистрированный домен или поддомен, А-запись которого **уже направлена на IP вашего сервера**.
- **Secret Key:** Секретный ключ ноды, полученный в панели управления RemnaWave.

## 🚀 Пошаговый процесс установки

После запуска инсталлятор последовательно запросит:

1. **Origin-домен**: Домен, на который выпускается сертификат Let's Encrypt и который используется для маскировки (например, `node.mydomain.com`).
2. **Email**: Email-адрес для регистрации в ACME/Let's Encrypt (по умолчанию: `admin@<ваш-домен>`).
3. **Шаблон маскировки**: Выбор внешнего вида сайта-заглушки (от 1 до 11).
4. **Secret Key**: Секретный ключ из панели RemnaWave (запрашивается **после** успешной установки и проверки SelfSteal).

## 🛡️ Ключевые инженерные решения скрипта

### 1. Автоматическое решение проблемы `needrestart` и `whiptail`
В современных версиях Ubuntu (особенно 22.04 и 24.04) при обновлении библиотек через `apt` утилита `needrestart` вызывает интерактивное диалоговое окно `whiptail`, блокируя работу скриптов.
Инсталлятор решает эту проблему **двухуровневой защитой**:
1. **Превентивно:** Создает переопределяющий файл `/etc/needrestart/conf.d/99-remnanode-auto.conf` с параметром `$nrconf{restart} = 'a';` и выставляет переменные окружения `DEBIAN_FRONTEND=noninteractive`, `NEEDRESTART_MODE=a`.
2. **Реактивно:** В фоновом режиме запускает сторожевой процесс (watchdog). Если какой-либо дочерний процесс все же вызывает `whiptail`, watchdog немедленно обнаруживает его PID и отправляет сигнал подтверждения в `/proc/$PID/fd/0`.

### 2. Защита от сбоев DNS и Let's Encrypt Rate Limit
Перед запросом сертификата Let's Encrypt скрипт через Cloudflare DoH и Google DoH проверяет, куда резолвится домен. Если DNS еще не обновился, скрипт предложит подождать распространения DNS в реальном времени с таймером, предотвращая блокировку аккаунта по лимитам Let's Encrypt.

### 3. Полная идемпотентность
- Скрипт не переустанавливает Docker, если он уже присутствует в системе.
- Существующие конфигурации `docker-compose.yml` автоматически бэкапятся с временной меткой.
- При повторном запуске существующие контейнеры плавно обновляются без сбоев.

### 4. Автоматическая верификация каждого этапа
Инсталлятор не просто выполняет команды, а валидирует результат:
- Проверка статуса контейнеров через `docker inspect`.
- Проверка прослушивания порта 80.
- Проверка наличия и прав Unix-сокета `/dev/shm/nginx.sock`.
- Проверка валидности сертификата и издателя через `openssl x509`.
- Проверка HTTP -> HTTPS редиректа с кодом 301 через локальный `curl`.
- Проверка доступности сокета изнутри контейнера `remnanode`.

## ⚙️ Настройка в панели RemnaWave

После завершения работы установщика откройте панель **RemnaWave** и добавьте/отредактируйте входящее подключение (Inbound) для протокола **VLESS Reality**:

```json
{
  "serverNames": ["ваш-домен.com"],
  "target": "/dev/shm/nginx.sock",
  "xver": 1
}
```

> **Важно:** 
> - `target` обязательно должен указывать на Unix-сокет `/dev/shm/nginx.sock`.
> - `xver` обязательно равен `1` (Proxy Protocol v1 для Nginx).

## 🤖 Неинтерактивный запуск (CI/CD / Автоматизация)

Вы можете передать все параметры в виде аргументов командной строки или переменных окружения для полностью автоматического развертывания без единого вопроса:

```bash
bash install.sh \
  --domain "reality.example.com" \
  --email "admin@example.com" \
  --template 4 \
  --secret-key "Ваш_Секретный_Ключ_Из_Панели" \
  --non-interactive
```

### Поддерживаемые флаги:

| Флаг | Описание |
|------|----------|
| `--domain <domain>` | Origin-домен для узла и сертификата |
| `--email <email>` | Контактный email для регистрации в ACME |
| `--template <1-11>` | Номер шаблона сайта-заглушки (по умолчанию: `4`) |
| `--secret-key <key>` | Secret Key узла из панели RemnaWave |
| `--non-interactive`, `-y` | Запуск в автоматическом режиме без интерактивных запросов |
| `--skip-dns-check` | Пропустить предварительную проверку резолва DNS |
| `--help`, `-h` | Показать справку по параметрам |

## 🔧 Встроенные утилиты управления

После установки в систему автоматически инсталлируются глобальные команды:

### 1. Комплексная диагностика узла
```bash
remna-check
```
*Выводит полную таблицу статусов контейнеров, сетевых портов, прав на сокет, сроков действия SSL-сертификата и последних строк логов.*

### 2. Безопасное удаление
```bash
remna-uninstall
```
*Корректно останавливает Docker-сервисы, очищает созданные каталоги `/opt/remnanode` и `/opt/nginx-selfsteal`, удаляет сокет и системные конфиги.*

### 3. Просмотр логов в реальном времени
```bash
# Логи RemnaNode
docker logs -f remnanode

# Логи SelfSteal Nginx
docker logs -f nginx-selfsteal
```

## ❓ Troubleshooting (Решение возможных проблем)

### 1. Сертификат Let's Encrypt не выпускается
- Убедитесь, что порт 80 свободен на хосте: `ss -tlnp | grep :80`.
- Проверьте, что в файрволе (UFW или iptables) открыты порты 80 и 443:
  ```bash
  ufw allow 80/tcp
  ufw allow 443/tcp
  ```
- Проверьте привязку домена: `dig +short your-domain.com @1.1.1.1`. IP должен совпадать с IP сервера.

### 2. RemnaNode не подключается к панели RemnaWave
- Проверьте корректность Secret Key:
  ```bash
  cat /opt/remnanode/docker-compose.yml
  ```
- Проверьте логи ноды:
  ```bash
  docker logs --tail 50 remnanode
  ```
- Убедитесь, что сервер имеет исходящий доступ к панели RemnaWave по порту ноды (по умолчанию 2222).

### 3. Клиенты Reality получают ошибку соединения
- Проверьте наличие сокета: `ls -la /dev/shm/nginx.sock`.
- Убедитесь, что в конфигурации Inbound в панели RemnaWave указано:
  - `"target": "/dev/shm/nginx.sock"`
  - `"xver": 1`
  - `"serverNames": ["ваш-домен.com"]`
